# 罗德岛许愿墙系统

一个可自部署、可配置、支持多终端访问的抽取式奖励系统
（网页端抽取 + 管理端配置）

## 一、项目目的（Why）
### 1. 核心目标

构建一个可部署在个人服务器上的许愿墙系统，实现：

- 外部用户（手机 / 电脑）访问一个页面 → 进行抽取 / 翻牌 / 许愿
- 系统根据预设规则 → 返回对应奖励
- 管理者通过后台页面 → 自由配置每个“签位”的奖励内容、概率、数量

一句话版：你决定“墙后面藏着什么”，用户只负责抽。

### 2. 使用场景

- 游戏活动 / 社群活动
- 内部年会 / 抽奖
- 线上许愿 / 随机奖励
- 展示型互动页面（大屏 / 平板）

### 3. 设计原则

- 自部署：不依赖第三方平台
- 可配置：不写死奖励，不改代码就能换内容
- 可控性强：概率可控、次数可控、保底可控
- 多端访问：PC / 手机浏览器直接用
- 前后端分离：便于扩展与维护

## 二、系统整体架构（What）
### 1. 总体结构（一句话）

一个「前台抽取页面 + 后台配置页面 + 后端服务 + 数据库」的 Web 系统

### 2. 架构示意（逻辑层）
```
┌─────────────┐        ┌──────────────┐
│  用户浏览器 │ ─────▶ │  抽取前端页面 │
│ (PC / 手机) │        └──────┬───────┘
└─────────────┘               │ API
                               ▼
                       ┌────────────────┐
                       │   后端服务 API  │
                       │  抽奖逻辑 / 校验 │
                       └──────┬─────────┘
                              │
                ┌─────────────┴─────────────┐
                ▼                             ▼
        ┌──────────────┐           ┌────────────────┐
        │   数据库      │           │   管理后台页面 │
        │ 奖励 / 配置   │ ◀──────── │  奖励配置 / 规则 │
        └──────────────┘           └────────────────┘
```

### 3. 模块拆分

####（1）抽取前端（Public UI）

- 完全对外
- 复刻「许愿墙」视觉与交互
- 职责：展示墙、接收点击、显示抽取结果
- 不包含任何抽奖逻辑（防作弊）

####（2）管理后台（Admin UI）

- 需要登录，仅管理员使用
- 配置每个“签位”的内容
- 设置概率 / 数量 / 是否已抽完
- 查看抽取记录

####（3）后端服务（核心大脑）

- 所有抽奖逻辑在这里
- 职责：校验抽取资格、执行抽奖算法、记录结果、返回前端展示数据

####（4）数据库（记忆）

- 存储：奖池定义、每个签位内容、抽取记录、用户 / 设备信息（可选）

## 三、核心功能设计（How）
### 1. 抽取流程

**用户视角**

1. 打开网页
2. 看到一整面「许愿墙」
3. 点击某一张
4. 动画翻开
5. 显示奖励

**系统视角**

点击 → 请求 API → 校验 → 抽奖 → 记录 → 返回结果

### 2. 奖励配置模型（核心）

每一个“签位”可配置字段：

| 字段 | 说明 |
| --- | --- |
| id | 唯一标识 |
| title | 显示名称 |
| description | 描述 |
| type | 奖励类型（积分 / 实物 / 空签） |
| weight | 权重（用于概率） |
| stock | 剩余数量 |
| image | 展示图 |
| enabled | 是否可抽 |

你看到的“看起来很多签”，本质是一个奖池 + 显示布局。

### 3. 抽奖算法（可扩展）

**初期建议**

- 加权随机（weight）
- 抽到即扣库存
- 无库存自动跳过

**后期可扩展**

- 保底机制（N 次必出）
- 每日限制
- 用户黑白名单

### 4. 防作弊与公平性

- 前端只展示，不计算
- 每次抽取由后端生成结果
- 可绑定：IP / User-Agent / Cookie / Token

### 5. 参考页面要素（UI 说明）

以下内容来自参考页面截图（Refer/喀兰圣山许愿墙.jpg），用于还原前台抽取页：

- 背景：虚化场景图 + 半透明浮层卡片
- 顶部左侧：剩余可选次数（例如 2/2）
- 顶部右侧：关闭按钮（X）（注：截图中有，该项目不需要）
- 中央主体：斜向排列的“许愿签”卡片矩阵
        - 默认态为封面图
        - 翻开后展示奖励内容
- 右侧中下：主操作按钮（“请选择许愿签”）
- 底部横条：规则摘要（RULE1 / RULE2）+ 活动结束时间

交互要点：

- 点击单张卡片触发翻牌动画
- 显示结果后禁用已选卡片
- 根据剩余次数更新左上角数字
- 点击右上角关闭按钮返回/退出

## 四、技术选型（Tech Stack）
### 1. 前端（抽取页 & 管理页）

**推荐组合**

- 框架：Vue 3 或 React 18
- 构建：Vite
- 样式：Tailwind CSS 或 纯 CSS + 动画
- 动画：CSS Transform 或 GSAP

**原因**

页面动画多、状态复杂，用现代前端更稳定、可维护。

### 2. 后端（API 服务）

**推荐组合**

- 语言：Node.js (TypeScript) 或 Python (FastAPI)
- API 风格：REST
- 鉴权：管理端 JWT / 用户端匿名 Token

**原因**

抽奖逻辑不重，关键是清晰、可维护、可扩展。

### 3. 数据库

- 首选：PostgreSQL
- 轻量：SQLite（单机可用）

数据结构清晰，不需要 NoSQL。

### 4. 部署方式

一台服务器即可。

推荐：

- Nginx
- 后端服务
- 前端静态文件

Nginx 路由建议：

```
/		→ 抽取页面
/admin	→ 管理后台
/api	→ 后端接口
```
